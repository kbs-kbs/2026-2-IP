# 2차시 산술 코딩과 LZW 코딩

## 1. 산술 코딩

- **비블록 코드**: 소스 기호와 코드 단어 사이에 1:1 대응이 존재하지 않는 코드. 소스 기호들의 전체 시퀀스에 하나의 산술 코드를 할당하고, 코드 단어 자체가 0과 1 사이의 실수 구간을 정의한다.
- 메시지 안의 기호 수가 늘어날수록 구간이 좁아지고, 그만큼 정보 단위 수가 늘어난다.

### 1.1 부구간 분할

| 기호 | 확률 | 초기 부구간 |
|---|---|---|
| a1 | 0.2 | [0.0, 0.2) |
| a2 | 0.2 | [0.2, 0.4) |
| a3 | 0.4 | [0.4, 0.8) |
| a4 | 0.2 | [0.8, 1.0) |

- 기호를 하나 읽을 때마다 현재 구간을 그 기호의 비율로 다시 나눈다. 메시지 `a1 a2 a3 a3 a4`의 과정:

| 단계 | 기호 | 구간 |
|---|---|---|
| 1 | a1 | [0.0, 0.2) |
| 2 | a2 | [0.04, 0.08) |
| 3 | a3 | [0.056, 0.072) |
| 4 | a3 | [0.0624, 0.0688) |
| 5 | a4 | [0.06752, 0.0688) |

- 최종 구간 안의 값 하나(예: 0.068)가 메시지 전체를 표현한다. 기호 5개를 3비트씩 쓰는 15비트 대신 짧은 실수 하나로 표현되는 셈이다.

### 1.2 복호 과정

1. 0.068은 [0.0, 0.2)에 포함 → 첫 기호 a1
2. 0.068은 [0.04, 0.08)에 포함 → 두 번째 a2
3. 0.068은 [0.056, 0.072)에 포함 → 세 번째 a3
4. 0.068은 [0.0624, 0.0688)에 포함 → 네 번째 a3
5. 0.068은 [0.06752, 0.0688)에 포함 → 다섯 번째 a4

- 부호기와 복호기가 같은 확률표를 공유하므로, 같은 구간 분할을 반복해 기호를 하나씩 되찾는다.

| 항목 | 허프만 | 산술 코딩 |
|---|---|---|
| 코드 단위 | 기호마다 코드 할당 | 메시지 전체에 하나의 실수 구간 |
| 최적성 | 기호 단위 조건에서 최적 | 기호 확률을 더 정밀하게 반영, 이론적 엔트로피에 근접 |
| 구현 | 간단, 빠름 | 구간 연산이 필요해 상대적으로 복잡 |

## 2. LZW 코딩

- 코딩 시작 시 소스 기호를 포함하는 코드북(사전)을 만든다. 인코더가 영상 픽셀을 순차적으로 조사하고, 사전에 없는 밝기 시퀀스는 알고리즘이 정한 위치에 할당한다.
- 8비트 단색 영상이면 사전의 처음 256개 단어에 밝기 0~255를 할당하고, 256번부터 새 시퀀스를 등록한다.

### 2.1 예제

$4 \times 4$ 영상이 행마다 `39 39 126 126`으로 반복되는 경우:

| 단계 | 현재 문자열 | 다음 출력 | 사전 추가 |
|---|---|---|---|
| 1 | 39 | 39 | 256: 39-39 |
| 2 | 39 | 126 | 257: 39-126 |
| 3 | 126 | 126 | 258: 126-126 |
| 4 | 126 | 39 | 259: 126-39 |
| 5 | 39 | 39 | 260: 39-39-126 |
| 6 | 39-39-126 | 256 | 261: 126-126-39 |
| … | … | … | … |

- 출력 코드: `39-39-126-126-256-258-260-259-257-126`
- 처음에는 1픽셀 단위로 출력하다가, 사전에 등록된 긴 시퀀스(256, 258, 260…)로 점점 긴 문자열을 한 코드로 표현한다. 반복이 많은 영상일수록 압축률이 높아진다.
- 복호기는 인코더가 만든 사전을 같은 규칙으로 재구성하므로 사전을 따로 전송하지 않는다.

## 3. 연속 길이 코딩과 기호 기반 코딩

### 3.1 연속 길이 코딩(RLE)

- 행(또는 열)을 따라 반복되는 밝기를 갖는 영상에서 동일 밝기의 연속을 **연속 길이 쌍**으로 표현한다.
- 각 쌍은 새로운 밝기의 시작과 그 밝기를 갖는 연속 픽셀 수를 규정한다. 이진 영상 압축에 효과적이며, 한 행을 좌에서 우로 스캔하며 만나는 1 또는 0의 인접 그룹을 길이로 코딩한다.

| 표준 | 내용 |
|---|---|
| CCITT Group 3 | 1D 연속 길이 코딩 기법 |
| CCITT Group 4 | Group 3의 간략·스트림라인 버전, 2D 코딩만 가능 |

### 3.2 기호 기반 코딩

- 영상을 자주 발생하는 부영상(기호)의 집합으로 표현하고, 각 기호를 기호 사전에 저장한 뒤 영상을 **트리플릿** 집합으로 코딩한다.

$$
\{(x_1, y_1, t_1),\ (x_2, y_2, t_2),\ \cdots\}
$$

- $(x_1, y_1)$: 영상에서 기호의 위치, $t_1$: 사전에서 기호(부영상)의 주소.
- 반복되는 기호를 한 번만 저장하므로 문자 비트맵처럼 같은 글자가 여러 번 나오는 문서 저장·검색에서 큰 압축 효과를 낸다.
- 기호 매칭 알고리즘 발전과 CPU 성능 향상으로 최근 실용화되었고, 트리플릿 자체를 인코딩해 압축 성능을 더 높일 수 있다. 무손실 압축 방식이다.

### 3.3 비트 평면 코딩

- 연속 길이·기호 기반 기법은 비트 평면을 개별 처리함으로써 3가지 이상의 밝기를 갖는 영상에도 적용할 수 있다.
- 다중 레벨 영상을 일련의 이진 영상으로 분해하고 이진 압축 기법으로 압축한다.
- 예: $f(x,y) = 80 = 01010000_2$이면 각 비트를 $b_8, b_7, \cdots, b_1$로 분리한다. $80 = 1 \times 2^6 + 1 \times 2^4$에 해당하는 비트만 1이다.
- 상위 비트 평면은 영상 구조를, 하위 비트 평면은 미세한 잡음 같은 정보를 담는다.

### 3.4 블록 변환 코딩

```
입력 영상(M×N) → n×n 부영상 구성 → 순방향 변환 → 양자화 → 기호 인코더 → 압축 영상
압축 영상 → 기호 디코더 → 역변환 → n×n 부영상 병합 → 압축 해제 영상
```

- 영상을 같은 크기(예: $8 \times 8$)의 중첩되지 않는 작은 블록으로 나누고, 각 블록을 2차원 변환으로 독립 처리한다. 역변환이 가능한 선형 변환(예: 푸리에 변환, DCT)을 쓴다.

| 구분 | 내용 |
|---|---|
| 적응적 변환 코딩 | 변환 코딩의 전체 또는 일부 단계가 부영상 내용에 적응 |
| 비적응적 변환 코딩 | 모든 부영상에 고정 |
| 부영상 크기 | 변환 오차와 계산 복잡성에 영향. 인접 부영상 간 상관이 수용 가능한 정도로 작아질 때까지 키우며, 2의 거듭제곱으로 구성 |

### 3.5 JPEG

| 시스템 | 내용 |
|---|---|
| 베이스라인 | DCT 기반 손실 압축. 대부분의 압축 응용에 적합 |
| 확장 | 더 큰 압축성, 높은 정밀성, 점진적 복구 응용 |
| 무손실 독립 | 가역 압축을 위한 무손실 시스템 |

### 3.6 예측 코딩

- 계산 오버헤드 없이 좋은 압축률과 무오차·무손실을 얻는 단순한 접근법이다.
- 각 픽셀에서 새로운 정보만 추출해 코딩함으로써 가까운 픽셀들의 중복성을 제거한다.

```
f(n) → (+) → e(n) → 기호 인코더 → 압축 시퀀스
        ↑ (-)
      예측기 f'(n)

압축 시퀀스 → 기호 디코더 → e(n) → (+) → f(n)
                                    ↑
                                  예측기 f'(n)
```

- 예측기 $f'(n)$은 이전 픽셀들로 다음 값을 추정하고, 인코더는 실제값과 예측값의 차이 $e(n)$만 부호화한다. 복호기는 같은 예측기로 원값을 복원한다.

### 3.7 웨이블릿 코딩

- 영상 픽셀을 비상관시키는 변환 계수가 원래 픽셀보다 효율적으로 코딩될 수 있다는 개념에 근거한다.
- 웨이블릿 기저가 중요한 시각 정보를 적은 수의 계수에 집약하면, 나머지 계수는 거의 왜곡 없이 양자화하거나 0으로 절삭할 수 있다.

```
입력 영상 → 웨이블릿 변환 → 양자화기 → 기호 인코더 → 압축 영상
압축 영상 → 기호 디코더 → 웨이블릿 역변환 → 압축 해제 영상
```

## 4. 디지털 영상 워터마킹

- 디지털 미디어와 인터넷 보급으로 배포된 저작권 영상의 반복적·무오차 불법 복제가 성행하면서 필요해졌다.
- **워터마크**: 불법 복제 방지를 위해 영상에 삽입된 정보 항목. 정보와 데이터를 영상에 추가하는 것이다.

| 목적 | 내용 |
|---|---|
| 저작권 보호 | 소유권 증명 |
| 판권 식별 | 배포 경로 추적 |
| 사용자 식별·지문 감정 | 복제자 추적 |
| 정통성 판정 | 위·변조 확인 |
| 자동 감시 | 배포 감시 시스템 |
| 복사 방지 | 복제 차단 |

| 종류 | 특징 | 적용 |
|---|---|---|
| 가시적 워터마크 | 관찰자에게 분명한 불투명·반투명 부영상. 공간 도메인에서 수행 | 저작권 표시 |
| 비가시적 워터마크 | 영상이 조금만 변경되어도 파괴되는 워터마크 | 영상 인증 등 |

- 비가시적 워터마크는 고화질 압축·해제 후에도 추출 여부로 견고성을 평가한다.

## 핵심 정리

- 산술 코딩은 메시지 전체를 하나의 실수 구간으로 표현해 엔트로피에 가깝게 압축한다.
- LZW는 사전을 점진적으로 만들어 반복 시퀀스를 한 코드로 바꾸는 무손실 기법이다.
- RLE는 반복 밝기의 연속 길이를, 기호 기반 코딩은 반복 부영상을 트리플릿으로 표현한다.
- 비트 평면·블록 변환(DCT 기반 JPEG)·예측·웨이블릿 코딩이 실용 압축의 축을 이룬다.
- 워터마킹은 가시·비가시 워터마크로 저작권 보호와 인증을 수행한다.
